# EduCraft Phase 1 產品範圍

> 文件狀態：Phase 1 基準草案
> 適用範圍：`educraft/` 現有 GitHub Pages 前端，以及其目前呼叫的 Supabase Auth、資料表、RPC 與 Edge Functions 介面
> 原則：先把既有備課核心做穩、可驗證、可追溯，再擴充新功能

## 1. 產品定位

EduCraft Phase 1 定位為：

> **台灣國小教師的可驗證 AI 備課與教案工作台。**

它協助教師從班級條件、教學風格與語言需求建立教案，保留課綱、來源、授權、版本及公開狀態，並讓教師在發布前完成專業判斷。EduCraft 不是自動替教師做教學決策的系統，也不是完整校務、學生或家長平台。

Phase 1 只追求三個結果：

1. 教師能建立、修改、保存並匯出一份可繼續校訂的教案。
2. 私人資料與公開資料有明確、可測試的邊界。
3. 每份教案的產生方式、課綱核對狀態、參考來源與授權可以被辨識。

## 2. 現有基準與未驗證事項

以下是目前 `educraft/` 原始碼可確認的產品基準，Phase 1 應相容而不是重做：

- 未登入時以瀏覽器 `localStorage` 保存教案、收藏與偏好；登入後前端會呼叫 Supabase 進行帳號與雲端同步。
- 帳號頁已有 Email/密碼、Email 登入連結與密碼重設入口。
- 私人教師資料與公開教師名片使用不同的前端表單及資料來源；公開名片需由使用者主動啟用。
- 教案預設在私人工作區；公開教案需登入、啟用公開名片、選擇授權並確認權利與個資檢查。介面已有撤回操作，但公開查詢是否確實停止顯示仍需後端驗證。
- 產生器已有十種教學風格：素養導向、5E、PBL、STEAM、CLIL、UDL、遊戲化、閱讀理解、SEL 與明確教學。
- 多語輸出中，繁體中文、英文、日文、韓文、越南文、印尼文與泰文有專用結構文字；其他語言會標示為待專業教師校訂的結構化草稿。
- ChatGPT 共備入口與認領頁已存在。前端契約為 12 碼轉移碼、登入後認領、匯入私人草稿，不把 EduCraft 登入權杖交給 ChatGPT。
- 教案可在本機編輯、建立版本、備份，並輸出 Markdown、JSON、DOCX、PDF 或列印。

下列事項不能只由此 repo 證明，需在 Phase 1 以測試或後端設定另行驗證：

- Supabase 各資料表、公開 view 與 RPC 的實際 schema、RLS 政策及匿名存取結果。
- MCP 工具實作、轉移碼是否確實 24 小時失效且只能認領一次。
- 複製教案已採 private-by-default：副本清除公開狀態、公開 slug、發布時間及雲端識別欄位，由回歸測試保護。
- 教育大市集正式 API Key、即時資料完整性與使用授權；降級或示範資料不得宣稱為即時官方資料。
- 外部生成服務的模型、品質與可用性；目前介面已允許模板模式，不能把模板產生標成外部 AI 產生。

## 3. 目標受眾

### 3.1 核心受眾

- 台灣國小一至六年級導師與科任教師。
- 需要快速調整學生程度差異、教學節數、設備、評量與議題融入的教師。
- 雙語、本土語、特教或其他需要多語草稿與合理調整提示的教師。
- 初任、代理及實習教師；所有產出仍須由實際授課教師核對。

### 3.2 次要受眾

- 學年共同備課團隊、教學設計師與課程輔導人員，先以教案交換、審閱及版本比較需求為主。
- 師培單位與教師社群，先作為測試、回饋及範本治理參與者，不在 Phase 1 建立機構管理功能。

### 3.3 本階段不服務的主要受眾

- 學生與家長帳號。
- 校務行政、成績、出缺勤或健康資料管理者。
- 需要完整 LMS、校務系統或教育局統計平台的機構採購者。

## 4. 產品邊界

### 4.1 Phase 1 範圍內

- 國小教案的建立、編輯、版本、備份、匯出與私人保存。
- 教學風格與多語輸出選擇；非完整支援語言須清楚標示待校訂。
- 私人教師資料、公開教師名片、私人教案與公開教案的區隔。
- 教案公開、撤回、授權選擇、原創說明及外部來源標示。
- ChatGPT MCP 共備後，以一次性轉移流程匯入私人草稿。
- 課綱與來源的可追溯資料契約；AI 不得自行把推測內容冒充正式課綱代碼。
- 現有靜態網站、Supabase 介面與 service worker 的基本可靠性、無障礙及手機版防回歸。
- CI、安全掃描、最小 E2E 與可重現的發布前檢查。

### 4.2 邊界外／需另案決策

- 學生名冊、成績、作業繳交、學習歷程、出缺勤及家長通訊。
- Google Classroom、Microsoft 365、Moodle、Canvas、LTI、OneRoster 等正式雙向串接。
- 多人即時協作、校內審核流、組織多租戶與付費方案。
- 自動爬取整批民間教案、出版社教材或未明確授權內容。
- 自動發布公開教案、自動修改正式課綱資料或無人工審核的知識庫更新。
- 多模型路由、向量資料庫、H5P、原生手機 App 或完整 Teacher OS。

這些項目只有在核心流程穩定、教師研究證明有需求，且資料與授權風險已評估後才立項。

## 5. 治理角色與決策權

角色以責任定義，不預設必須增加全職人力；一人可兼任多個角色，但同一項高風險發布不可由同一人同時提出並完成全部核准。

| 角色 | 主要責任 | 最終決策權 |
| --- | --- | --- |
| 產品負責人 | 定義使用情境、排序工單、控制 Phase 1 範圍與發布節奏 | 範圍、優先序、是否立項；不得覆寫安全否決 |
| 教學產品負責人 | 代表國小教學現場，驗收教案流程、語言提示與可用性 | 教學流程及內容呈現是否可交付教師測試 |
| 課綱／來源管理者 | 維護官方來源、版本、課綱對應與授權紀錄 | 可否標示為正式課綱或可引用來源 |
| 技術維護者 | 維持前端、Supabase 介面相容、CI、測試、監控與回復方案 | 架構、合併與技術發布；高風險變更可拒絕發布 |
| 隱私與安全負責人 | 審核 RLS、認證、公開資料面、日誌及資料保留 | 個資、權限或憑證風險具有發布否決權 |
| 教師測試小組 | 以真實備課任務測試，回報不可用情境與教學風險 | 是否達成教師驗收指標；不直接修改正式資料 |

決策規則：

1. 課綱、授權、個資或帳號權限不明時，先維持私人／草稿／示範狀態。
2. Supabase schema、RLS、MCP 或公開 view 的變更必須獨立 PR、回復步驟與對應測試，不與純前端樣式修改混合。
3. 正式發布至少需要技術維護者確認自動檢查通過；涉及教案結構或公開內容時，另需教學或來源角色確認。
4. AI 可以整理錯誤、提出修補與補測試，不得自行合併權限、個資、正式資料或公開發布相關變更。

## 6. 功能優先序

### 6.1 P0：Phase 1 必須穩定的核心

| 能力 | Phase 1 要求 |
| --- | --- |
| 結構化教案契約 | 定義可版本化的教案 schema，涵蓋基本資料、教學流程、學習證據、差異化、評量、課綱、來源、授權與原創說明；既有 `planJson` 與 Markdown 必須可相容 |
| 建立與編輯 | 現有表單、十種風格、多語提示、編輯、自動保存、版本及匯出流程不可回歸；模板與外部 AI 來源須如實標示 |
| 私人／公開分流 | 私人資料不可由匿名或其他帳號讀取；公開頁只能讀取使用者主動公開的欄位及教案；撤回後不得再出現在公開查詢面 |
| 帳號與本機模式 | 未登入可使用本機私人工作區；登入／註冊入口可達；雲端失敗時不得覆寫本機資料，介面須誠實顯示狀態 |
| ChatGPT MCP 匯入 | 維持「聊天室建立轉移、EduCraft 登入認領、先存私人草稿、另行確認公開」的流程；不得傳送 EduCraft 密碼或 session token 給聊天室。基礎後端 contract E2E 是 Phase 1 後續 P0 gate，不是本次純前端里程碑的 live test |
| 課綱與來源追溯 | 每個正式課綱關聯及外部素材須有來源、版本／日期與授權狀態；未核對內容標成待核對，不產生虛構官方代碼 |
| 發布保護 | 公開前要求權利、來源、授權與學生個資確認；公開頁顯示作者、原創說明、教學框架及授權 |
| 品質閘門 | JavaScript、HTML/CSS 基本檢查、關鍵檔案、service worker cache 版本、CodeQL 與最小 E2E 在 PR 自動執行 |
| 手機與無障礙 | 首頁、共備、帳號、公開庫在手機 viewport 可操作，無殘留全頁遮罩；基本鍵盤焦點、標籤與對比不得退化 |

### 6.2 P1：P0 通過後才排入

- 依結構化教案衍生學習單、離堂票、題目、Rubric 與簡報大綱；先輸出可編輯文件，不自建完整簡報平台。
- 課綱與官方來源的版本差異通知與人工審核佇列；不允許自動改寫既有教案。
- 教師對教案可用性、錯誤類型與修改量的結構化回饋，供評測使用；不得收集學生可識別資料。
- 共享連結或審閱副本的最小流程；多人即時編輯另案評估。
- 針對已確認授權的官方／OER 來源做有限搜尋串接，保留原始網址、來源狀態與降級提示。
- 在基礎 MCP contract E2E 通過後，加入端點健康趨勢、錯誤分類與不含內容的操作性監控。

P1 不因列入本文件而自動授權實作；每項仍需獨立工單、驗收條件及資料風險審查。

## 7. 明確非目標

Phase 1 不以以下結果為成功標準：

- 宣稱 AI 產出可免除教師校訂、可取代教師，或已獲教育主管機關認證。
- 宣稱已連接教育部「所有」國小科目資料，除非有來源清單、更新時間、授權及完整性測試。
- 追求最多模型、最多串接或最多教案風格。
- 複製、改寫或模仿特定民間教師、出版社或網站的教案文字。
- 建立學生資料庫、教師績效評分或自動化高風險教育決策。
- 在未驗證 RLS、備份與回復前調整正式 Supabase schema。

## 8. 原創、參考與授權原則

1. **參考方法，不複製表達。** 可採用 5E、PBL、STEAM、CLIL、UDL 等公開教學框架及一般專業結構，不得抓取、拼貼或仿寫單一民間教案全文與獨特表達。
2. **來源逐筆保存。** 外部素材至少記錄標題、發布者、原始網址、授權或權利狀態、取得／核對日期；不能確認時標示「授權待確認」，且不得直接收錄內容。
3. **AI 產生不等於原創或合法。** 產生方式、教師修改與人工核對狀態要可辨識；教師在公開前仍須確認權利、事實、課綱與授權。
4. **授權由發布者明確選擇。** 不從來源或教學風格推論授權；公開頁須顯示所選授權，撤回公開不等於撤銷已依既有授權取得的使用權。
5. **保留衍生關係。** 日後若支援複製公開教案，必須保存原作者、原版本、原授權及改作說明；Phase 1 不把一般「複製私人教案」宣稱為合法公開改作。
6. **示範資料要明示。** 無正式 API 或來源驗證時，資料必須標示為示範／降級資料，不得使用會讓教師誤認為即時官方資料的文案。

## 9. 資料安全界線

- EduCraft 只收集完成教師帳號、備課與公開名片所必要的資料。Phase 1 不收集學生姓名、學號、聯絡方式、照片、診斷、健康、家庭或其他可識別敏感資料。
- 班級情境、程度差異與合理調整一律使用去識別化描述；輸入欄位與 ChatGPT 提示都應提醒此限制。
- 私人資料與公開資料是不同資料面。公開必須是明確 opt-in，Email、私人學校欄位、私人簡介、私人筆記、草稿及未發布版本不得因前端篩選錯誤而外洩。
- 前端 `user_id` 篩選不是安全邊界；真正隔離必須由 Supabase RLS、受控 view／RPC 與自動化匿名／跨帳號測試保證。
- 密碼與 session token 交由 Supabase Auth 處理，不寫入 repo、URL、教案內容、分析事件或錯誤日誌。公開 publishable key 不等於可省略 RLS。
- ChatGPT MCP 只能接收共備所需資料與轉移內容，不得讀取無關聊天室或取得 EduCraft 登入權杖。轉移碼必須限時、一次性、不可預測，且認領後先落在私人草稿。
- `localStorage` 是單一裝置的便利保存，不是加密保險箱。共用裝置或瀏覽器帳號可能讓他人看到本機資料；介面與文件需說明備份、清除及雲端刪除是不同動作。
- 公開發布前必須再次檢查學生個資、外部素材、授權與來源。自動檢查只能提示，不能取代發布者確認。
- 正式監控與除錯資料應最小化；不得記錄密碼、token、完整私人教案、轉移碼或學生敏感資訊。

## 10. 成功指標

### 10.1 產品結果

- 至少 10 位核心受眾教師完成一次「建立或匯入 → 修改 → 保存 → 匯出」任務，其中至少 80% 可在不需開發者協助下完成。
- 至少 80% 的測試教師判定輸出可作為備課草稿，且能指出課綱核對、來源與待校訂狀態。
- 所有公開教案樣本都能追溯作者公開名片、原創說明、教學框架、授權及發布狀態。
- 匿名與第二帳號存取私人教師資料、私人教案及版本的測試結果皆為拒絕或空集合；目標為 0 筆外洩。
- ChatGPT 測試轉移皆先進入正確帳號的私人草稿；過期、重複認領、未登入及無效碼都有可理解的失敗結果。

### 10.2 品質與發布

- 每個 PR 的 CI、CodeQL 與最小 E2E 必須通過，或由維護者在 PR 明確記錄例外與風險；不得靜默略過。
- E2E 至少覆蓋首頁、ChatGPT 共備入口、登入／註冊頁、公開教案庫及手機 viewport 無幽靈遮罩。
- Phase 1 期間不得因本里程碑修改或破壞既有 Supabase schema、RLS、正式端點或 GitHub Pages 路徑。
- P0 事件一旦造成私人資料公開、無法登入／認領、資料覆寫或全站不可用，必須停止發布並回復上一個已驗證版本。

## 11. 第一個里程碑驗收

本次里程碑完成的判定條件如下：

- [ ] 產品範圍文件經產品、教學及安全角色審閱，P0、P1 與非目標無衝突。
- [ ] 架構文件定義教案 schema、私人／公開資料流、MCP 認領與課綱／來源追溯模型，並標出目前未驗證的後端假設。
- [ ] GitHub Actions 可重現執行 JavaScript 語法、HTML/CSS 基本、關鍵檔案及 service worker cache version 檢查。
- [ ] Playwright 最小 E2E 覆蓋五個指定情境，且不依賴真實教師帳號或寫入正式資料。
- [ ] Dependabot 或 Renovate 與 CodeQL 已設定；更新 PR 仍需人工審核，不自動部署高風險變更。
- [ ] M1 commit 只包含文件與品質基礎設施；M3 後續 commit 可加入經 rollback 驗證的 migration，但 CI／GitHub Pages 不得自動套用或修改正式資料。
- [ ] PR 說明列出測試結果、未完成風險、後端待驗證契約及下一階段工單。

## 12. Phase 1 完成前的必要工單

1. ✅ 複製教案已固定 private-by-default，並留下公開來源副本的回歸測試。
2. ✅ 核心路由已在等待 `getSession()` 前啟用；`data-router-ready`／`data-app-ready` 與延遲 session 測試固定核心及擴充模組契約。
3. ✅ 已驗證並記錄 Supabase RLS、公開 view 與跨帳號存取矩陣；發現的 claim／version 缺口已進入待套用 migration。
4. 對 MCP initialize、tools contract、24 小時到期、一次性認領與私人落地建立端對端測試。
5. ✅ 已以相容性測試固定結構化教案 schema，並實作既有 `planJson`／Markdown 的唯讀相容與不自動回寫策略。
6. ✅ 已建立第一批課綱及來源清冊，區分來源狀態、人工審核與授權待確認；逐份課綱文件與版本內容仍屬後續擴充。
